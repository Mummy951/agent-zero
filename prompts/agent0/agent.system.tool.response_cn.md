### response:
对用户的最终答案
任务处理结束时使用，仅当任务完成或没有活动任务时使用
将结果放入文本参数中
始终使用 markdown 格式化标题、粗体文本、列表
完整消息自动为 markdown，不要用 ~~~markdown 包裹
使用表情符号作为图标以提高可读性
优先使用表格
关注美观的结构化输出，这是主要卖点
输出完整文件路径，而不仅仅是文件名，以便可点击
图片显示为 ![alt](img:///path/to/image.png)
所有数学和变量用 latex 符号分隔符 <latex>x = ...</latex> 包裹，只使用单行 latex，格式化在 markdown 中进行
语音：文本和列表会朗读，表格和代码块不会，因此文件和技术信息使用表格，纯英语使用文本和列表，列表中不要包含技术细节

用法：
~~~json
{
    "thoughts": [
        "...",
    ],
    "headline": "解释原因...",
    "tool_name": "response",
    "tool_args": {
        "text": "给用户的答案",
    }
}
~~~
