# 架构概览
Agent Zero 构建于灵活模块化的架构之上，旨在实现可扩展性和定制化。本节概述了其关键组件及其之间的交互。

## 系统架构
此简化图示了代理之间的层次关系以及它们与工具、扩展、仪器、提示、内存和知识库的交互。

![Agent Zero 架构](res/arch-01.svg)

用户或 Agent 0 处于层级结构的顶端，将任务委托给下属代理，下属代理可以进一步委托给其他代理。每个代理都可以利用工具并访问共享资产（提示、内存、知识、扩展和仪器）来执行其任务。

## 运行时架构
Agent Zero 的运行时架构围绕 Docker 容器构建：

1. **宿主系统 (您的机器)**:
   - 仅需 Docker 和 Web 浏览器
   - 运行 Docker Desktop 或 Docker Engine
   - 处理容器编排

2. **运行时容器**:
   - 包含完整的 Agent Zero 框架
   - 管理 Web UI 和 API 端点
   - 处理包括代码执行在内的所有核心功能
   - 提供跨所有平台的标准化环境

此架构确保：
- 跨平台环境一致性
- 简化部署和更新
- 通过容器化增强安全性
- 减少对宿主系统的依赖要求
- 为高级用户提供灵活的部署选项

> [!NOTE]
> 直接在宿主系统上运行 Agent Zero 的传统方法（使用 Python、Conda 等）
> 仍然可行，但需要通过“设置”页面进行远程函数调用 (RFC) 配置。
> 有关详细说明，请参阅 [完整二进制文件安装](installation.md#in-depth-guide-for-full-binaries-installation)。

## 核心组件
Agent Zero 的架构围绕以下关键组件：

### 1. 代理
框架内的核心参与者。代理接收指令、推理、决策，并利用工具实现其目标。代理在分层结构中操作，上级代理将任务委托给下级代理。

#### 代理层级和通信
Agent Zero 采用分层代理结构，其中顶级代理（通常是用户）可以将任务委托给下级代理。这种层级结构有助于将复杂任务高效地分解为更小、更易于管理的子任务。

代理之间的通信通过消息进行，这些消息根据提示模板进行结构化。这些消息通常包括：

| 参数 | 描述 |
| --- | --- |
| `Thoughts:` | 代理的思维链和规划过程 |
| `Tool name:` | 代理使用的特定工具 |
| `Responses or queries:` | 来自工具或其他代理的结果、反馈或查询 |

#### 交互流程
Agent Zero 中典型的交互流程可能如下所示：

![交互流程](res/flow-01.svg)

1. 用户向 Agent 0 提供指令
2. Agent 0 初始化 VectorDB 并访问内存
3. Agent 0 分析指令并使用 `thoughts` 参数制定计划，可能涉及使用工具或创建子代理
4. 如有必要，Agent 0 将子任务委托给下属代理
5. 代理使用工具执行操作，既提供参数也提供响应或查询
6. 代理将结果和反馈传回层级结构
7. Agent 0 向用户提供最终响应

### 2. 工具
工具是代理可以利用的功能。这可以包括从网络搜索和代码执行到与 API 交互或控制外部软件的任何功能。Agent Zero 提供了一种定义和集成内置及自定义工具的机制。

#### 内置工具
Agent Zero 带有一组内置工具，旨在帮助代理高效地执行任务：

| 工具 | 功能 |
| --- | --- |
| behavior_adjustment | Agent Zero 使用此工具根据用户之前的请求更改其行为。 |
| call_subordinate | 允许代理将任务委托给下属代理 |
| code_execution_tool | 允许代理在终端中执行 Python、Node.js 和 Shell 代码 |
| input | 允许代理使用键盘与活动 shell 交互 |
| knowledge_tool | 使代理能够从内存、知识库或在线外部源检索信息 |
| response_tool | 允许代理输出响应 |
| memory_tool | 使代理能够从内存中保存、加载、删除和遗忘信息 |
| webpage_content_tool | 使代理能够获取和分析网页的文本内容 |

#### 知识工具
`knowledge_tool` 使用 SearXNG 搜索网络并检索信息。它还可以搜索本地知识库和内存以获取相关信息。该工具返回信息的摘要，代理可以使用该摘要来做出决策或回答问题。

#### SearXNG 集成
Agent Zero 已将 SearXNG 集成作为其主要的搜索工具，取代了之前的知识工具（Perplexity 和 DuckDuckGo）。此集成增强了代理检索信息的能力，同时确保了用户隐私和定制化。

- 注重隐私的搜索
SearXNG 是一个开源元搜索引擎，允许用户搜索多个来源而无需跟踪其查询。此集成确保用户数据在访问广泛信息的同时保持私密和安全。

- 增强的搜索能力
此集成提供了对各种类型内容（包括图像、视频和新闻文章）的访问，允许用户收集有关任何主题的全面信息。

- 后备机制
在 SearXNG 可能无法返回令人满意结果的情况下，Agent Zero 可以配置为回退到其他来源或方法，确保用户始终可以访问信息。

> [!NOTE]
> 知识工具旨在与通过 SearXNG 进行的在线搜索和本地知识库查询无缝协作，
> 提供全面的信息检索系统。

#### 自定义工具
用户可以创建自定义工具以扩展 Agent Zero 的功能。自定义工具可以通过定义工具规范集成到框架中，其中包括要放置在 `/prompts/$FOLDERNAME/agent.system.tool.$TOOLNAME.md` 中的工具提示，如下所述。

1. 在 `prompts/$SUBDIR` 中创建 `agent.system.tool.$TOOL_NAME.md`
2. 在 `agent.system.tools.md` 中添加引用
3. 如有需要，在 `python/tools` 中使用 `Tool` 基类实现工具类
4. 遵循现有模式以保持一致性

> [!NOTE]
> 工具始终存在于系统提示中，因此应将其保持在最低限度。
> 为了节省令牌，请使用 [仪器模块](#adding-instruments)
> 调用自定义脚本或函数。

### 3. 内存系统
内存系统是 Agent Zero 的关键组件，使代理能够从过去的交互中学习和适应。它采用混合模型，其中部分内存由框架自动管理，而用户也可以手动输入和提取信息。

#### 内存结构
内存分为四个不同的区域：
- **用户提供信息的存储和检索**（例如，名称、API 密钥）
- **片段**: 包含来自先前对话的信息片段，自动更新
- **解决方案**: 存储过去交互中的成功解决方案以供将来参考
- **元数据**: 每个内存条目都包含元数据（ID、时间戳），可以根据特定标准进行高效过滤和搜索。

#### 消息历史和总结

Agent Zero 采用复杂的消息历史和总结系统，以在有效维护上下文的同时优化内存使用。该系统动态管理信息流，确保相关细节随时可用，同时有效处理上下文窗口的限制。

- **上下文提取：** 系统从先前消息中识别对持续讨论至关重要的关键信息。此过程类似于人类回忆重要记忆的方式，允许不那么关键的细节逐渐淡化。
- **总结过程：** Agent Zero 通过实用模型使用自然语言处理将提取的信息浓缩为简洁的摘要。通过总结过去的交互，Agent Zero 可以快速回忆有关整个聊天的重要事实，从而产生更合适的响应。
- **上下文相关性：** 总结的上下文根据其与当前主题的相关性进行优先级排序，确保用户收到最相关的信息。

**实施细节：**

- **消息摘要**：单个消息使用结构化格式进行总结，以捕获关键信息同时减少令牌使用。
- **动态压缩**：系统采用智能压缩策略：
  - 最近的消息以原始形式保留，以用于即时上下文。
  - 较旧的消息逐渐压缩为更简洁的摘要。
  - 多个压缩级别允许高效利用上下文窗口。
  - 原始消息与摘要分开保存。
- **上下文窗口优化**：
  - 作为单次对话的近乎无限的短期记忆。
  - 根据可用空间和设置动态调整压缩比。
- **批量和主题总结**：
  - 将相关消息分组为主题块，以便更好地组织。
  - 生成多条消息的简洁摘要，同时保留关键上下文。
  - 能够高效导航长对话历史。
  - 维护相关主题之间的语义连接。

通过动态调整上下文窗口和总结过去的交互，Agent Zero 提高了效率和用户体验。这项创新不仅体现了框架对动态和以用户为中心的承诺，还汲取了人类认知过程的灵感，使 AI 交互更具关联性和有效性。就像人类会忘记琐碎的细节一样，Agent Zero 会智能地压缩信息以增强沟通。

> [!NOTE]
> 为了最大限度地提高上下文总结的有效性，用户应在交互过程中提供清晰具体的说明。
> 这有助于 Agent Zero 理解哪些细节最重要以保留。

### 4. 提示
`prompts` 目录包含控制代理行为和通信的各种 Markdown 文件。最重要的文件是 `agent.system.main.md`，它充当中心枢纽，引用其他提示文件。

#### 核心提示文件
| 提示文件 | 描述 |
|---|---|
| agent.system.main.role.md | 定义代理的整体角色和能力 |
| agent.system.main.communication.md | 指定代理应如何通信 |
| agent.system.main.solving.md | 描述代理处理任务的方法 |
| agent.system.main.tips.md | 提供额外的提示或指导 |
| agent.system.main.behaviour.md | 控制动态行为调整和规则 |
| agent.system.main.environment.md | 定义运行时环境上下文 |
| agent.system.tools.md | 组织和调用单个工具提示文件 |
| agent.system.tool.*.md | 单个工具提示文件 |

#### 提示组织
- **默认提示**: 位于 `prompts/default/`，作为基本配置
- **自定义提示**: 可以放置在自定义子目录中（例如，`prompts/my-custom/`）
- **行为文件**: 作为 `behaviour.md` 存储在内存中，包含动态规则
- **工具提示**: 组织在特定于工具的文件中，以实现模块化

#### 自定义提示
1. 在 `prompts/` 中创建目录（例如，`my-custom-prompts`）
2. 从 `prompts/default/` 复制并修改所需文件
3. Agent Zero 将您的自定义文件与默认文件合并
4. 在“设置”页面（代理配置部分）中选择您的自定义提示

#### 动态行为系统
- **行为调整**：
  - 代理可以根据用户指令实时修改其行为
  - 行为更改会自动集成到系统提示中
  - 行为规则智能合并，避免重复和冲突

- **行为管理组件**：
  - `behaviour_adjustment.py`：更新代理行为的核心工具
  - `_20_behaviour_prompt.py`：将行为规则注入系统提示的扩展
  - 自定义规则作为 `behaviour.md` 存储在代理的内存目录中

- **行为更新过程**：
  1. 用户请求行为更改（例如，“用英式英语回应”）
  2. 系统识别对话中的行为指令
  3. 新规则与现有规则集合并
  4. 更新的行为立即生效

![行为调整](res/ui-behavior-change-chat.png)

- **与系统提示集成**：
  - 行为规则注入到系统提示的开头
  - 规则以结构化 Markdown 格式进行格式化
  - 更改在不中断其他组件的情况下应用
  - 保持核心功能和行为规则之间的分离

> [!NOTE]
> 您可以自定义这些文件中的任何一个。如果您的自定义 `prompts_subdir` 中存在文件，
> Agent Zero 将使用它们，否则，它将回退到 `prompts/default` 中的文件。

> [!TIP]
> 行为系统允许动态调整，而无需修改基本提示文件。
> 通过行为规则所做的更改在会话中持久存在，同时保持核心功能。

### 5. 知识
知识是指代理可以利用的用户提供的信息和数据：

- **自定义知识**: 手动或通过 UI 中的“导入知识”按钮将文件添加到 `/knowledge/custom/main` 目录
  - 支持的格式：`.txt`、`.pdf`、`.csv`、`.html`、`.json`、`.md`
  - 自动导入和索引
  - 可扩展的格式支持

- **知识库**:
  - 可以包括 PDF、数据库、书籍、文档
  - 自动添加 `/docs` 文件夹
  - 用于回答问题和决策
  - 支持 RAG 增强任务

### 6. 仪器
仪器提供了一种向 Agent Zero 添加自定义功能的方法，而无需增加系统提示的令牌计数：
- 存储在 Agent Zero 的长期记忆中
- 提供无限数量的仪器
- 代理在需要时召回
- 可以通过引入新程序来修改代理行为
- 函数调用或脚本以与其他系统集成
- 脚本在 Docker 容器内运行

#### 添加仪器
1. 在 `instruments/custom` 中创建文件夹（名称中无空格）
2. 添加 `.md` 描述文件用于接口
3. 添加 `.sh` 脚本（或其他可执行文件）用于实现
4. 代理将自动检测并使用仪器

### 7. 扩展
扩展是 Agent Zero 的强大功能，旨在保持主代码库的整洁和有序，同时提供更大的灵活性和模块化。

#### 结构
扩展可以在 `python/extensions` 目录中找到：
- **文件夹组织**: 扩展存储在与代理消息循环不同方面对应的指定子文件夹中
- **执行顺序**: 文件按字母顺序执行以实现可预测的行为
- **命名约定**: 文件以数字开头以控制执行顺序
- **模块化**: 每个扩展都专注于特定功能

#### 类型
- **消息循环提示**: 处理系统消息和历史构建
- **内存管理**: 处理召回和解决方案记忆
- **系统集成**: 管理与外部系统的交互

#### 添加扩展
1. 在适当的 `python/extensions` 子文件夹中创建 Python 文件
2. 遵循命名约定以控制执行顺序（以数字开头）
3. 按照现有模式实现功能
4. 确保与主系统兼容
5. 部署前进行彻底测试
