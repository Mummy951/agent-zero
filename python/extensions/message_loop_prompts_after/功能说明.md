# message_loop_prompts_after 扩展功能说明

## 功能概述
`message_loop_prompts_after` 扩展在代理的消息循环中，主语言模型（LLM）生成回复之后，但在将最终提示发送给LLM之前执行。它主要负责通过集成相关记忆、解决方案、工具和当前时间信息来增强LLM的提示，从而使LLM能够生成更丰富、更具上下文意识和更准确的响应。

## 详细功能
1. **召回记忆 (`_50_recall_memories.py`)**:
   - 在每隔一定迭代次数后，异步地从记忆数据库中检索与当前对话最相关的历史记忆。
   - 通过对话历史生成查询，并利用相似性搜索匹配记忆。
   - 将检索到的记忆作为额外上下文添加到LLM的提示中，帮助LLM更好地理解长期对话和用户意图。

2. **召回解决方案和工具 (`_51_recall_solutions.py`)**:
   - 类似于记忆召回，此组件异步地从知识库中检索与当前任务相关的预定义解决方案和可用工具。
   - 这些解决方案和工具可以指导LLM在特定场景下采取行动或提供特定类型的响应。
   - 将检索到的信息添加到LLM的提示中，扩展LLM的能力范围。

3. **包含当前日期时间 (`_60_include_current_datetime.py`)**:
   - 获取当前的UTC日期和时间，并将其格式化为可读的本地时间字符串。
   - 将此日期时间信息作为额外的上下文添加到LLM的提示中，使得LLM能够处理和响应时间敏感的查询。

4. **等待召回完成 (`_91_recall_wait.py`)**:
   - 确保由 `_50_recall_memories.py` 和 `_51_recall_solutions.py` 启动的所有异步记忆和解决方案召回任务已经完成。
   - 这对于保证LLM在处理提示时，所有相关的上下文信息都已完全加载和可用至关重要，避免LLM基于不完整的信息生成响应。

## 用途
`message_loop_prompts_after` 扩展是代理智能和上下文感知能力的核心组成部分。通过动态地丰富LLM的提示，它使得代理能够：
- 更好地记忆和利用过去的对话信息。
- 根据预设的知识和工具提供更专业的帮助。
- 处理需要当前时间信息的任务。
- 确保在生成响应前所有相关信息的准备就绪，从而提高响应的质量和相关性。
